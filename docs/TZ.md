# ТЗ: Сампо — запись на самоподготовку по парным танцам

Документ для агентов, которые реализуют сервис. Продуктовые правила ниже обязательны. Если правила не хватает, остановись и спроси, а не расширяй скоуп.

Фронтенд зафиксирован заказчиком: **React + Webpack + SCSS**. Не заменяй его на Vite, CRA, Next, CSS-in-JS или Tailwind.

Бэкенд подтверждён заказчиком: **Node.js + Fastify + PostgreSQL**.

## Как выполнять работу

1. Прочитай документ целиком, затем бери **одну** задачу из раздела «Нарезка для агентов».
2. Не меняй стек, правила записи, свободы и машину состояний запроса.
3. Переходы запроса и пары делай только в одном доменном модуле `server/src/domain/sampo.js`. HTTP-слой этот модуль не дублирует.
4. Тексты интерфейса и уведомлений — на русском.
5. Время в базе — `timestamptz` (UTC). Единственный локальный пояс — `Asia/Yekaterinburg` (Тюмень и Екатеринбург, UTC+5, без летнего времени). Константа `TIME_ZONE` лежит в `shared/timezone.js`. Календарь, слоты, окна свободы, день недели и подпись `{when}` считаются только в этом поясе. Пояс браузера, сервера и `Europe/Moscow` не использовать.
6. Не добавляй оплату, чат, email, мультитенантность, нативные приложения и рейтинг.

## 1. Назначение

Сампо — веб-приложение, которое ставится на телефон как PWA. Участники студии парных танцев:

- входят по логину и паролю или через ВКонтакте;
- видят календарь слотов самоподготовки;
- записываются на слот без партнёра («Я приду»);
- отмечают, когда их можно пригласить: на конкретном слоте или окном времени — один раз, каждый день, по будням, по выходным или каждые n дней;
- отправляют другому участнику запрос на пару в конкретный слот;
- подтверждают или отказывают в приложении, в push-уведомлении и, если аккаунт связан с ВК, в личных сообщениях сообщества.

Подтверждённый запрос создаёт пару на этот слот. Оба становятся записанными, если ещё не были. Запись без пары и пара живут рядом: можно прийти одному, а пару собрать приглашением.

## 3. Вне скоупа v1

- Оплата, абонементы, посещаемость для бухгалтерии.
- Переписка, комментарии к запросу, жалобы.
- Несколько клубов и роли персонала кроме одного администратора.
- Email, восстановление пароля, телефон, SMS.
- Роль в паре, уровень, направление танца, фильтры людей по этим полям.
- Окна свободы через полночь и слоты, которые по времени Тюмени заканчиваются позже 23:30.
- Нативные iOS/Android-приложения. Только PWA.
- Тёмная тема, i18n, публичные профили вне сервиса.

## 4. Роли

**Гость.** Экран входа. Новый профиль создаётся только через ВК. Календарь и люди скрыты.

**Участник.** Календарь, запись на слот, окна свободы, запросы, пара, профиль, push, привязка ВК.

**Администратор.** Создание, правка и отмена слотов, регистрация пользователя по логину, паролю и имени, правка и удаление чужих профилей. Своего профиля танцора нет: администратор не записывается, не отмечает свободу и не участвует в приглашениях. Чужой профиль администратора удалить нельзя. Первый администратор задаётся переменными `SEED_ADMIN_LOGIN` и `SEED_ADMIN_PASSWORD` при пустой таблице пользователей. Роль в интерфейсе не выдаётся.

## 5. Глоссарий

| Термин | Смысл |
| --- | --- |
| Слот | Окно самоподготовки в зале: начало, конец, место, вместимость, статус `open` или `cancelled`. |
| Запись | Участник идёт на этот слот. Пары может не быть. Занимает одно место. |
| Окно свободы | Интервал, когда участника можно звать: разовый или один и тот же день недели. |
| Отметка слота | Явная свобода именно на этом слоте. |
| Исключение | Слот закрыт для приглашений, даже если его накрывает окно. |
| Свободен | Участника можно пригласить на слот по правилу из раздела 7. |
| Запрос | Приглашение от одного участника другому на один слот. |
| Пара | Двое договорились заниматься вместе на слоте. Оба при этом записаны. |
| Занят | У участника уже есть запись на пересекающийся слот. |

Интервалы пересекаются, если `a.startsAt < b.endsAt` и `b.startsAt < a.endsAt`.

## 6. Сценарии

### 6.1 Регистрация и вход

1. Участник входит через ВК. Сервис создаёт аккаунт без пароля, имя берёт из ВК, сохраняет `vk_user_id`. Самостоятельной регистрации по логину и паролю нет: такой аккаунт создаёт только администратор.
2. В профиле можно задать логин и пароль и дальше входить ими. Если логин уже есть, его можно сменить; пустой пароль при этом не меняет текущий.
3. После входа открывается календарь.
4. Если вход был через ВК, следом показывается шаг «Разрешите сообщения сообщества» со ссылкой на диалог сообщества. Без этого ВК не доставит личные сообщения.
5. Сервис один раз за сессию просит разрешение на push. Отказ не блокирует работу. Повторный запрос — из профиля.

Аккаунт один. Парольный пользователь может привязать ВК. Пользователь ВК может задать логин и пароль. Если этот `vk_user_id` уже занят другим аккаунтом, привязка отклоняется. Автослияния аккаунтов нет.

### 6.2 Запись без пары

1. Участник открывает будущий открытый слот и нажимает «Я приду».
2. Запись занимает одно место. Повторное нажатие ничего не меняет.
3. Отказ, если мест нет или у участника уже есть запись на пересекающийся слот.
4. «Не приду» снимает запись, только пока на этом слоте нет активной пары и слот не начался.
5. Запись никого не уведомляет и сама по себе не значит «меня можно пригласить».

### 6.3 Когда меня можно пригласить

1. На слоте участник включает «Свободен для приглашения» или снимает отметку.
2. Либо в разделе «Когда я свободен» добавляет окно на выбранное время: один раз, каждый день, по будням (если выбран будний день), по выходным (если выбран выходной) или каждые n дней, считая от выбранной даты.
3. Окно делает человека свободным на всех будущих слотах, которые с ним пересекаются хотя бы частично. Касание ровно в границе не считается пересечением.
4. Если окно накрывает слот, а человек не хочет приглашений именно туда, выключение тумблера ставит исключение на этот слот.
5. Нельзя стать свободным на отменённом или уже начавшемся слоте и на слоте, который пересекается с другой своей записью.
6. Снятие свободы и удаление окна не отменяют уже отправленные и полученные запросы.

### 6.4 Запрос

1. Участник открывает слот и видит, кого можно пригласить.
2. В списке только свободные на этот слот, кроме него самого. Поиск по имени, без учёта регистра.
3. Записанный на этот слот без пары в списке есть, если он свободен. Записанный на другое пересекающееся время — нет.
4. Отправитель выбирает человека и отправляет запрос. Сам отправитель может быть ещё не записан.
5. Адресат получает событие во внутренний ящик, push (если подписан) и сообщение ВК (если есть `vk_user_id`).
6. Адресат подтверждает или отказывает. Отправитель, пока запрос `pending`, может только отозвать его.

### 6.5 Подтверждение

1. Создаётся пара на этот слот.
2. Обоим создаётся запись, если её ещё не было. Уже существующая запись вторым местом не считается.
3. Оба перестают быть свободными на этом слоте: явная отметка снимается, исключение ставится, чтобы еженедельное окно не оставило их в списке.
4. Прочие `pending`-запросы обоих, чьи слоты пересекаются с этим, переводятся в `cancelled` с причиной `superseded`.
5. Оба получают уведомление о подтверждении. Авторам снятых запросов уходит отдельное уведомление, что время уже занято.

### 6.6 Отказ, отмена, истечение

- Адресат отказал: запрос `declined`. Отправитель уведомлён. Записи и свобода не меняются.
- Отправитель отозвал `pending`: запрос `cancelled`, причина `withdrawn`. Адресат уведомлён.
- Наступило `startsAt`, а запрос всё ещё `pending`: статус `expired`. Оба уведомлены коротко, без кнопок.
- Участник пары отменяет пару до `startsAt`: пара `cancelled`, записи обоих остаются. Второй уведомлён. Свобода сама не возвращается: чтобы снова звали, отметку или окно нужно включить заново. После начала слота пару отменить нельзя.
- «Не приду» при активной паре недоступно, пока пара не отменена.
- Администратор отменяет слот: слот `cancelled`, пары `cancelled`, `pending`-запросы `cancelled` с причиной `slot_cancelled`, записи, отметки и исключения этого слота удаляются. Уведомление уходит каждому, у кого была запись или `pending`-запрос, один раз.

## 7. Правила

Участник свободен на слоте, если одновременно:

- слот `open` и ещё не начался;
- нет записи на другой слот, пересекающийся с этим;
- нет активной пары на этом или на пересекающемся слоте;
- нет исключения на этот слот;
- есть явная отметка на слот или окно, которое пересекается со слотом.

Окно пересекается со слотом:

- разовое: интервалы пересекаются, `window.startsAt < slot.endsAt` и `slot.startsAt < window.endsAt`;
- каждый день: местные интервалы времени пересекаются;
- по будням: день слота по Тюмени — понедельник–пятница, и местные интервалы пересекаются;
- по выходным: день слота — суббота или воскресенье, и местные интервалы пересекаются;
- каждые n дней: дата слота не раньше даты начала, разница в сутках делится на n, и местные интервалы пересекаются;
- еженедельное (только уже сохранённые окна): день недели слота по времени Тюмени совпадает, и местные интервалы времени пересекаются.

День недели хранится как ISO: понедельник `1` … воскресенье `7`. Слот по времени Тюмени начинается и заканчивается в одну календарную дату и не позже 23:30. Окно не переходит через полночь.

1. Нельзя пригласить себя.
2. Нельзя пригласить того, кто не свободен на этот слот.
3. Нельзя создать второй `pending`-запрос с той же тройкой (слот, отправитель, адресат).
4. У отправителя не больше одного `pending`-исходящего запроса на пересекающиеся слоты.
5. У адресата может быть несколько входящих `pending`. Он выбирает один. Остальные пересекающиеся снимаются при подтверждении.
6. Нельзя отправить запрос, если слот не `open`, уже начался, или у отправителя есть запись на другой пересекающийся слот, активная пара на пересечении либо другой исходящий `pending` на пересечении. Запись отправителя на этот же слот запросу не мешает.
7. «Я приду» занимает место сразу. Подтверждение пары занимает место только тем из двоих, у кого записи на этот слот ещё нет. Если `занято + новые > capacity`, подтверждение возвращает `CAPACITY`, запрос остаётся `pending`.
8. `capacity` — целое число от 1 до 200. Место и вместимость можно менять у будущего слота, если новая вместимость не меньше числа записей. Начало и конец можно менять, только пока нет записей, активных пар и `pending`-запросов.
9. Длительность слота и разового окна — от 30 минут до 6 часов. Повторяющееся окно — от 30 минут, внутри одних суток и не позже 23:30. Интервал «каждые n дней» — целое n от 2 до 30.
10. Слоты в прошлом администратор не создаёт. Отмена слота разрешена, пока он не начался.
11. Повтор исходящего запроса тем же людям на тот же слот после `declined`, `cancelled` или `expired` разрешён: создаётся новый запрос.
12. Не более 10 созданных запросов в час и не более 30 окон свободы на пользователя.
13. Список людей и слоты доступны только после входа.
14. Включение свободы: удалить исключение и поставить явную отметку. Выключение: снять явную отметку и поставить исключение.

## 8. Модель данных

Идентификаторы — UUID. Имена колонок в базе — `snake_case`. В JSON API — `camelCase`.

| Колонка | Ограничение |
| --- | --- |
| id | uuid, pk |
| login | text, unique, nullable, 3–32 символа, латиница в нижнем регистре, цифры, `_` |

Запись «Я приду» или запись, созданная подтверждением пары. `user_id`, `slot_id`, `created_at`. Уникальность `(user_id, slot_id)`.

Явная отметка слота. `user_id`, `slot_id`, `created_at`. Уникальность `(user_id, slot_id)`.

`id`, `user_id`, `endpoint` unique, `p256dh`, `auth`, `created_at`.

### notifications

Внутренний ящик. Пишется в той же транзакции, что и смена статуса.

| Колонка | Смысл |

Доставка в push и ВК. В транзакцию смены статуса вставляется со статусом `pending`. Отправка идёт после commit.

## 9. Машина состояний

```text
pending → accepted     адресат
pending → declined     адресат
pending → cancelled    отправитель (withdrawn) или система (superseded, slot_cancelled)
pending → expired      система, когда now >= slot.startsAt
```

Из `accepted`, `declined`, `cancelled`, `expired` переходов нет. Повторный вызов того же действия возвращает текущее состояние и код 200, без второй пары и без второго уведомления.

### Подтверждение, одна транзакция

Функция `acceptRequest(requestId, actorUserId)`:

1. `SELECT … FOR UPDATE` запроса. Актор — `to_user_id`. Иначе 403.
2. Если статус не `pending`, вернуть текущий запрос.
3. Заблокировать слот. Если не `open` или уже начался — перевести запрос в `expired` или `cancelled/slot_cancelled` и выйти.
4. Заблокировать строки обоих пользователей (`SELECT … FROM users WHERE id IN (…) FOR UPDATE` в порядке uuid), чтобы два подтверждения не создали две пары.
5. Если у любого есть запись на другой пересекающийся слот или активная пара на этом либо пересекающемся слоте — 409 `CONFLICT`, запрос остаётся `pending`.
6. `need` — сколько из двоих ещё без записи на этот слот. Если `число записей слота + need > capacity` — 409 `CAPACITY`.
7. Создать недостающие записи. Вставить пару. Запросу выставить `accepted` и `responded_at`.
8. Снять явную свободу обоих на этом слоте и поставить им исключения, чтобы окно не оставило их в списке приглашений.
9. Все прочие `pending` этих двоих на пересекающихся слотах перевести в `cancelled` / `superseded`.
10. Вставить строки `notifications` и `notification_deliveries`.
11. Commit. Затем попытка доставки.

Отказ, отзыв отправителем, истечение, запись и отмена пары — функции того же модуля. Отмена пары разрешена только её участнику до начала слота и записи не удаляет. «Я приду» блокирует строку слота, повторно возвращает текущую запись. «Не приду» при активной паре возвращает 409 `PAIR_ACTIVE`.

Гонка «подтвердить» и «отозвать» решается блокировкой строки запроса: кто взял `pending` первым, тот и записал итог. Второй получает актуальное состояние.

### Сессия

- Access JWT живёт 15 минут, только в памяти клиента, заголовок `Authorization: Bearer`.
- Refresh — случайная строка, в базе хранится её хэш. Cookie `sampo_refresh`: `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` в production, срок 30 дней.
- В localStorage токены не писать.
- При старте приложения клиент вызывает refresh. Неудача ведёт на вход.
- Service worker для кнопок push вызывает API с `credentials: 'include'`. Отдельный секрет в payload push не класть.

Создание слота администратором:

```json
{
  "startsAtLocal": "2026-10-14T19:00",
  "endsAtLocal": "2026-10-14T21:00",
  "place": "Зал 1",
  "capacity": 20,
  "repeatWeekly": 0
}
```

`repeatWeekly` — сколько дополнительных таких же слотов создать через 7, 14, … дней. Максимум 12. Все слоты одной серии получают один `seriesId`. Удаление слота с `seriesId` спрашивает: только этот слот или все связанные. Уже начавшиеся слоты серии не удаляются.

Ответ слота в списке:

```json
{
  "id": "uuid",
  "startsAt": "2026-10-14T16:00:00.000Z",
  "endsAt": "2026-10-14T18:00:00.000Z",
  "place": "Зал 1",
  "capacity": 20,
  "status": "open",
  "taken": 4,
  "myAttendance": true,
  "myAvailability": false,
  "availabilitySource": null,
  "myPendingOutgoing": false,
  "myPendingIncomingCount": 0,
  "myPair": null
}
```

`taken` — число записей на слоте, а не число пар. `availabilitySource`: `explicit`, `window` или `null`. Для `window` в деталях слота дополнительно `windowLabel`, например «каждый вторник, 18:00–22:00».

Элемент списка свободных: `id`, `displayName`, `requestStatus` (`pending`, `accepted`, `declined`, `cancelled`, `expired` или `null`), `canInvite`. В списке также человек, с которым на этом слоте уже есть запрос, даже если пригласить его снова нельзя. Без логина и без id ВК.

Разовое окно:

```json
{ "kind": "once", "startsAtLocal": "2026-10-14T18:00", "endsAtLocal": "2026-10-14T22:00" }
```

Каждый день, будни или выходные:

```json
{ "kind": "daily", "localStart": "18:00", "localEnd": "22:00" }
```

`kind` здесь также `weekdays` или `weekends`.

Каждые n дней, считая от выбранной даты:

```json
{ "kind": "interval", "intervalDays": 3, "anchorDate": "2026-10-14", "localStart": "18:00", "localEnd": "22:00" }
```

Уже сохранённое еженедельное окно по-прежнему читается. Создать новое через форму нельзя; API его ещё принимает:

```json
{ "kind": "weekly", "weekday": 2, "localStart": "18:00", "localEnd": "22:00" }
```

## 11. Экраны

Мобильная вёрстка первая. Минимальная зона нажатия 44px. Статус слота дублируется текстом, не только цветом.

Общая оболочка после входа: сверху имя сервиса «Сампо», снизу навигация «Календарь», «Запросы», «Профиль». На запросах — счётчик непрочитанных входящих `pending`.

### Вход

- Логин и пароль, кнопка «Войти».
- Кнопка «Войти через ВКонтакте»: вход и единственный способ создать профиль.
- Подсказка, что логин и пароль задаются в профиле.
- Ошибки под формой текстом с сервера (`message`).

### Календарь `/calendar`

- Сетка по времени Тюмени с 9:00 до 23:30. На шкале и линиях только часы. Выбор времени шагом 30 минут, получасовые деления на экране не рисуются.
- Телефон: полоса из семи дат, ниже сетка выбранного дня.
- Шире 800px: семь дней колонками. Стрелки листают неделю.
- Слот — блок на своём диапазоне: время, зал, «занято N из capacity». Если слот отменён, на блоке текст «Отменён». Нажатие на блок открывает слот.
- Администратор задаёт время слота нажатием на клетку (получается 30 минут) или перетаскиванием курсора по диапазону. На телефоне второе нажатие задаёт конец диапазона. Затем указывает зал, вместимость и повтор по неделям.

### Слот `/slots/:id`

- Время, зал, вместимость, сколько мест занято.
- Кнопка «Я приду» или «Не приду». При активной паре «Не приду» скрыта, вместо неё текст «Сначала отмените пару».
- Переключатель «Свободен для приглашения». Если свобода пришла из окна, под тумблером подпись `windowLabel`.
- Если есть активная пара — имя партнёра и кнопка «Отменить пару» до начала слота. После отмены оба остаются в списке идущих.
- Блок входящих и исходящих запросов этого слота для меня.
- «Можно пригласить»: выпадающий список с поиском. В строке имя, иконка статуса подтверждения и кнопка «Пригласить». Отдельной кнопки приглашения в модалке нет.
- Пока у меня есть пересекающийся исходящий `pending` или запись на другое пересекающееся время, кнопки «Пригласить» недоступны, причина написана текстом.

### Когда я свободен `/me/availability`

- Список окон и удаление каждого.
- После выбора времени на сетке модалка: «Один раз», «Каждый день», «По будням» (если выбран будний день), «По выходным» (если выбран выходной), «Каждые n дней» с числом от 2 до 30. Время уже выбрано на сетке.
- Пустое состояние: «Окон нет. Вас можно пригласить только на отмеченные слоты».

### Запросы `/requests`

- Переключатель «Мне» и «Мои».
- Карточка: имя второго человека, слот, место, статус, кнопки по роли.
- Карточка одного запроса `/requests/:id` — тот же набор кнопок. Сюда ведёт push и ссылка из ВК.

### Профиль `/me`

- Имя.
- Ссылка на «Когда я свободен».
- Привязка или отвязка ВК.
- В дополнительных настройках блок «Вход по логину»: логин, пароль и повтор пароля. Пока пароля нет, он обязателен. Если логин уже задан, пустой пароль его не меняет.
- Администратор на `/me` видит только «Новый пользователь» и поиск «Пользователи», без своих настроек танцора и без уведомлений. Выбор открывает `/admin/users/:id` с тем же редактором профиля, логином и удалением. Ссылка «Пользователи» есть в меню аккаунта.
- Push: состояние разрешения и кнопки «Включить» / «Выключить».
- Если ВК привязан — ссылка «Открыть диалог сообщества» и короткая подсказка, что без разрешения сообщества личные сообщения не придут.
- Выход.

### Календарь администратора

Отдельного раздела «Слоты» нет: администратор создаёт и правит слоты в том же календаре `/calendar`. Ссылки «Как пользоваться?» у него нет.

- Время нового слота выбирается на сетке, без отдельных полей даты и времени.
- Клик по существующему слоту открывает окно. Время показано и не редактируется. Пока слот открыт и не начался, можно изменить зал и вместимость. «Удалить слот» удаляет его, пока он не начался. Если слот из серии на несколько недель, перед удалением выбор: «Только этот слот» или «Все связанные».

### Тексты кнопок

«Подтвердить», «Отказать», «Отозвать запрос», «Отменить пару», «Пригласить», «Я приду», «Не приду», «Свободен для приглашения».

### Визуальные токены

Один файл `client/src/styles/tokens.scss`. Компоненты берут только эти переменные.

- Фон `#f6f3ee`, карточка `#fffdf9`, текст `#1c1916`, вторичный текст `#6e675f`, линия `#e4ddd4`.
- Акцент кнопки `#9c3b2e`, белый текст на акценте.
- Подтверждено `#2f6f4e`, ожидание `#8a5a12`.
- Шрифт системный: `system-ui, "Segoe UI", sans-serif`. Сетевые шрифты не подключать: PWA должен открываться офлайн хотя бы оболочкой.
- Скругление 12px, тени не использовать.

Состояния загрузки и пустые списки («Слотов на этой неделе нет», «Свободных людей нет») обязательны. Ошибка сети — текст и кнопка «Повторить».

## 12. Авторизация

### Пароль

Логин нормализуется в нижний регистр. Пароль сравнивается через bcrypt. В ответе логина одинаковое сообщение на неизвестный логин и неверный пароль: «Неверный логин или пароль». Ограничение: 10 попыток входа в 15 минут на логин и на IP, в памяти процесса.

### ВКонтакте

Протокол VK ID, OAuth 2.1 + PKCE.

- Старт кладёт в короткоживущую cookie `state`, `code_verifier` и `purpose` (`login` или `link`).
- Callback проверяет `state`.
- Из ответа ВК сохраняется числовой id пользователя и имя.
- `purpose=login`: найти пользователя по `vk_user_id` или создать нового.
- `purpose=link`: записать `vk_user_id` текущему пользователю. Чужой id даёт `VK_ALREADY_LINKED`.
- Токен пользователя ВК не используется для отправки сообщений и не хранится дольше обмена кода.

Сообщество для уведомлений — отдельная настройка, не путать с приложением VK ID.

## 13. PWA и Web Push

### Установка

`client/public/manifest.webmanifest`:

- `name` и `short_name`: «Сампо»
- `start_url`: `/calendar`
- `scope`: `/`
- `display`: `standalone`
- `lang`: `ru`
- `background_color` и `theme_color` совпадают с фоном и акцентом
- иконки 192 и 512, непрозрачный фон, можно простые заглушки

Service worker регистрируется в production и на `localhost`. Кэширует оболочку (html, js, css, иконки). Запросы `/api` не кэширует. Офлайн-оболочка показывает «Нет сети», если API недоступен.

Webpack: `HtmlWebpackPlugin`, `MiniCssExtractPlugin` в production, копирование `manifest` и иконок, отдельная сборка service worker.

### Push

- Библиотека `web-push`, ключи VAPID в окружении.
- Публичный ключ отдаётся как `GET /api/push/public-key`.
- Подписка привязана к пользователю. Повторный endpoint обновляет ключи, а не плодит строки.
- Уведомление о входящем запросе содержит действия `accept` и `decline` с `requestId`.
- Где браузер не показывает действия (в том числе часть установок на iOS), клик открывает `/requests/:id`.
- Кнопка в service worker: `fetch` с cookie. Ответ 401 открывает экран запроса, а не повторяет запрос вслепую.
- iOS доставляет web push только установленному PWA и только с версии 16.4. Это ограничение платформы, отдельное приложение из-за него не делаем.
- Клик по обычному уведомлению открывает путь из `data.url`.

## 14. Уведомления

| type | Кому | Push | ВК | Текст |
| --- | --- | --- | --- | --- |
| request_received | адресат | да, с кнопками | да, с клавиатурой | «{name} приглашает вас на сампо {when}, {place}» |
| request_accepted | отправитель | да | да | «{name} подтвердил сампо {when}, {place}» |
| request_declined | отправитель | да | да | «{name} отказал в сампо {when}, {place}» |
| request_withdrawn | адресат | да | да | «{name} отозвал запрос на сампо {when}» |
| request_superseded | вторая сторона снятого запроса | да | да | «Запрос на сампо {when} снят: время уже занято» |
| request_expired | оба | да | да | «Запрос на сампо {when} истёк» |
| pair_cancelled | второй в паре | да | да | «{name} отменил сампо {when}, {place}» |
| slot_cancelled | каждый, у кого на слоте была запись или pending-запрос, один раз | да | да | «Сампо {when}, {place} отменено студией» |

`{when}` — дата и время начала по Тюмени, например «14 октября, 19:00».

Внутренний ящик создаётся на каждое из этих событий, даже если push и ВК пропущены.

### Доставка

После commit воркер раз в 15 секунд берёт `pending` доставки старше попытки, не больше 20 за проход, не больше 5 попыток. Между попытками пауза растёт: 15с, 1м, 5м, 15м. После пятой — `failed`. Ошибка одной доставки не откатывает запрос.

Истечение запросов: тот же тик переводит `pending`, у которых слот уже начался, в `expired`.

### ВКонтакте

Отправка: `messages.send` от имени сообщества токеном сообщества.

- `random_id` детерминированный от id доставки, чтобы повтор не создал второе сообщение.
- Для `request_received` — inline-клавиатура: «Подтвердить» и «Отказать», `payload` JSON `{ requestId, action }`.
- Остальные типы — текст и ссылка на сервис, без кнопок.
- Если ВК ответил, что пользователю нельзя написать, доставка `failed`, в профиль это не блокирует продукт. Подсказка про диалог сообщества показывается заранее.

Callback сообщества: `POST /api/vk/callback`.

- Проверка `secret` и `group_id`.
- Запрос `confirmation` отвечает строкой из `VK_CALLBACK_CONFIRMATION`.
- Событие `message_event`: по `user_id` ВК найти пользователя, он должен быть адресатом запроса, затем вызвать `acceptRequest` или `declineRequest`. Ответ Callback API — `show_snackbar` с итогом: «Сампо подтверждено», «Вы отказали», «Запрос уже закрыт» или текст ошибки вместимости.
- Чужой `user_id` или поддельный `requestId` не меняют данные.

## 15. Стек и репозиторий

```text
client/     React 18, Webpack 5, SCSS, React Router 6
server/     Node.js 22, Fastify, Drizzle ORM, PostgreSQL 16
docs/TZ.md
```

Клиент:

- точки входа `client/src/index.jsx`, `client/src/sw.js`;
- стили компонентов — CSS Modules (`*.module.scss`) рядом с компонентом;
- данные сервера — `@tanstack/react-query`;
- даты — `date-fns` и `date-fns-tz`, одна функция форматирования слота;
- HTTP — один `client/src/api/client.js`: подставляет access token, один раз обновляет сессию на 401 и повторяет запрос.

Сервер:

- схема Drizzle и SQL-миграции в `server/migrations`;
- конфиг только из окружения, без секретов в репозитории;
- домен в `server/src/domain/sampo.js`;
- тесты домена на `node:test`, без Jest.

Продакшен: один origin. Fastify раздаёт собранный `client/dist` и `/api`. Cookie тогда без кросс-доменной возни. В разработке webpack dev server проксирует `/api` на Fastify.

## 16. Нарезка для агентов

Каждая задача заканчивается рабочим вертикальным куском. Не начинай следующую, пока у текущей не выполнены критерии «готово».

### S1. Каркас

Монорепозиторий `client` и `server`, gitignore, `.env.example`, Fastify `GET /api/health`, Webpack-сборка React со стартовой страницей «Сампо», глобальные токены, манифест, пустой service worker оболочки.

Готово: `npm run dev` в клиенте открывает страницу, health отвечает, манифест доступен по своему URL.

### S2. Парольный вход

Миграция `users` и refresh-сессий, register/login/refresh/logout, сид администратора, экраны входа и регистрации, хранение access token в памяти, редирект на `/calendar` после входа.

Готово: новый пользователь входит, обновление страницы сохраняет сессию через cookie, неверный пароль не сообщает, существует ли логин.

### S3. Вход и привязка ВК

OAuth VK ID с PKCE, создание и поиск пользователя, привязка и отвязка, задание пароля аккаунту без логина.

Готово: сценарий с тестовым приложением ВК создаёт пользователя и вторым шагом привязывает ВК к парольному аккаунту. Повторная привязка чужого ВК возвращает `VK_ALREADY_LINKED`.

### S4. Слоты

Миграции слотов, админское API, экран администратора, публичный для сессии `GET /api/slots`.

Готово: администратор создаёт одиночный слот и серию из 2 недель, участник видит их в календаре по времени Тюмени, прошедший слот создать нельзя.

### S5. Календарь участника

Экран `/calendar` и `/slots/:id` без списка людей: сетка 9:00–23:30 с шагом 30 минут, состояния загрузки и отменённого слота.

Готово: на ширине 390px видна полоса дат и сетка одного дня, на 1100px — семь колонок, нажатие на блок слота открывает его.

### S6. Запись на слот

Таблица `attendances`, `POST` и `DELETE /api/slots/:id/attendance`, кнопки «Я приду» и «Не приду» на экране слота. `taken` в списке слотов — число записей.

Готово: повторная запись не создаёт вторую строку, пересекающийся слот и полная вместимость возвращают ошибку, чужую запись снять нельзя.

### S7. Свобода

Явные отметки, окна, исключения и функция «свободен на слоте» из раздела 7. Переключатель на слоте. Тесты: окно пересекается со слотом хотя бы частично, касание границы не считается, исключение скрывает человека, занятость другим слотом скрывает.

Готово: тесты зелёные. Еженедельный вторник 18:00–22:00 делает человека свободным на слоте этого вторника 19:00–21:00 без ручной отметки.

### S8. Запросы и пары

Доменный модуль, миграции запросов и пар, API, тесты `node:test`: подтверждение создаёт недостающие записи и не удваивает уже записанного, отказ, отзыв, вместимость с учётом чужих записей, пересечение, гонка двух подтверждений одного адресата, повторный accept, отмена пары сохраняет записи, «Не приду» при активной паре даёт `PAIR_ACTIVE`.

Готово: тесты домена зелёные, HTTP только вызывает модуль.

### S9. Экраны запросов

Список свободных, приглашение, `/requests`, карточка, кнопки подтверждения, отказа, отзыва и отмены пары.

Готово: два пользователя проходят приглашение → подтверждение и видят пару. Уже записанный участник пары занимает одно место, а не два. Если свободных мест меньше, чем число ещё не записанных из этой пары, API возвращает `CAPACITY`. Второй входящий на то же время после подтверждения становится `superseded`.

### S10. Ящик уведомлений

Запись уведомлений в транзакции, `GET /api/notifications`, отметка прочитанного, счётчик в навигации. Администратор уведомления не получает: колокольчика нет, записи не создаются, поток и API ящика ему недоступны. Доставка push и ВК ещё заглушка со статусом `skipped`, если канал не настроен.

Готово: подтверждение и отказ создают запись ящика второй стороне.

### S11. Web Push

VAPID, подписка в профиле, service worker, кнопки подтвердить и отказать, открытие `/requests/:id`.

Готово: на localhost подписка сохраняется, входящий запрос показывает системное уведомление, действие «Подтвердить» меняет статус, если cookie сессии жива.

### S12. Сообщения ВК

`messages.send`, клавиатура, Callback API, воркер повторов, ссылка на диалог сообщества в профиле.

Готово: тестовый пользователь, разрешивший сообщения сообщества, получает запрос с двумя кнопками, нажатие в ВК вызывает тот же доменный модуль, повтор callback не создаёт вторую пару.

### S13. Экраны свободного времени

Страница `/me/availability`: выбор времени на сетке, модалка повтора (один раз, каждый день, по будням или выходным, каждые n дней), удаление. На слоте виден источник свободы.

Готово: окно без ручной отметки показывает человека в «Можно пригласить». Выключение тумблера на накрытом слоте убирает его из списка. Поиск по имени без учёта регистра. В профиле нет полей роли, уровня и направления.

## 17. Приёмка целиком

1. Участник регистрируется паролем, нажимает «Я приду» на слот и отдельно отмечает, что свободен для приглашения. Второй участник входит через ВК и приглашает первого.
2. Первый подтверждает с телефона из push. У обоих на слоте пара, и оба есть в записях. Место первого не удваивается.
3. Другой участник может занять место только кнопкой «Я приду», без приглашения.
4. Участник с окном «каждый вторник 18:00–22:00» появляется в списке приглашений и на вторничный слот 19:00–21:00, и на слот 17:00–19:00, потому что второй только частично попадает в окно. На слот 10:00–11:00 он не появляется.
5. Третий пригласивший на время, которое уже занято парой, получает «время уже занято», его запрос больше не висит.
6. Отказ и отзыв не создают пару и не снимают чужую запись «Я приду».
7. Отмена пары оставляет обоих записанными. «Не приду» до отмены пары не срабатывает.
8. Два одновременных подтверждения разных запросов одного человека создают только одну пару.
9. Отмена слота администратором снимает записи и пару и уведомляет пришедших.
10. При установленной PWA на телефон открывается «Сампо» без адресной строки браузера, старт с календаря.
11. Пользователь с привязанным ВК получает личное сообщение сообщества и может ответить кнопкой.
12. Пользователь без ВК получает только ящик и push.
13. Чужой пользователь не подтверждает чужой запрос ни через API, ни через callback ВК.

## 18. Что нужно перед S3 и S12

Продуктовые решения закрыты. Для входа через ВК и личных сообщений нужны ключи приложения VK ID и сообщества: токен сообщений и Callback API. Пока ключей нет, агент делает остальные срезы и не подменяет ВК успешным входом.

## 19. Сервер

Агент сам заходит на боевой сервер и правит его. IP, логин и пароль лежат в `docs/server.local.md`. Этот файл в git не входит. Ключи приложения и пароли — только в локальном `server/.env` и в `/opt/sampo/server/.env` на сервере. После правки серверного `.env` перезапусти службу: `systemctl restart sampo`.

`VK_REDIRECT_URI` на боевом сервере — `https://vparaplane.ru/api/auth/vk/callback`. Локальный адрес `http://localhost/api/auth/vk/callback` туда не копировать.
